# 04 前后端如何连接

这是新手最困惑的一章。核心结论只有一句：

> **前端请求永远写 `/api/...` 这样的相对路径；开发时由 Rsbuild 代理到 3001，生产时由 Go 直接处理。**

## 开发模式：两个端口 + 一个代理

```
浏览器
  │ 打开 http://localhost:5173
  ▼
Rsbuild Dev Server (5173)
  │ 页面、JS、HMR 都由它提供
  │
  │ 匹配到 /api、/v1、/mj、/pg 前缀
  ▼
代理转发 → Go 后端 (3001)
```

配置文件 [web/rsbuild.config.ts](../web/rsbuild.config.ts)：

```ts
const serverUrl =
  process.env.VITE_REACT_APP_SERVER_URL ||
  env.rawPublicVars.VITE_REACT_APP_SERVER_URL ||
  'http://localhost:3001'

const devProxy = Object.fromEntries(
  (['/api', '/v1', '/mj', '/pg'] as const).map((key) => [
    key,
    { target: serverUrl, changeOrigin: true },
  ])
)

server: {
  port: devPort,       // 5173
  strictPort: true,
  proxy: devProxy,
}
```

环境变量文件 [web/.env.development](../web/.env.development)：

```ini
VITE_REACT_APP_SERVER_URL=http://localhost:3001
VITE_DEV_PORT=5173
```

所以开发时一次请求的完整路径是：

```
浏览器 GET http://localhost:5173/api/channel/?p=1
   ↓ Rsbuild 代理
Go     GET http://localhost:3001/api/channel/?p=1
```

浏览器只看到 5173，因此不存在跨域问题。

## 生产模式：一个端口 + 嵌入资源

生产构建后，Go 二进制里带着前端产物：

```go
// main.go
//go:embed web/dist
var buildFS embed.FS

//go:embed web/dist/index.html
var indexPage []byte
```

请求怎么分流，看 [router/main.go](../router/main.go) 和 [router/web-router.go](../router/web-router.go)：

```
GET /api/...    → api-router.go   （JSON 接口）
GET /v1/...     → relay-router.go （AI 转发）
GET /assets/... → 嵌入的静态文件
GET 其他任意路径 → 返回 index.html，交给前端路由处理（SPA 回退）
```

`web-router.go` 的核心逻辑：

```go
router.NoRoute(
    ...
    middleware.ServeFrontendFiles(frontendFS),   // 先尝试匹配静态文件
    func(c *gin.Context) {
        if strings.HasPrefix(c.Request.RequestURI, "/v1") ||
           strings.HasPrefix(c.Request.RequestURI, "/api") ||
           strings.HasPrefix(c.Request.RequestURI, "/assets") {
            controller.RelayNotFound(c)          // 这些前缀不能回退到 HTML
            return
        }
        c.Data(http.StatusOK, "text/html; charset=utf-8", assets.IndexPage)
    },
)
```

这就是为什么刷新 `/channels` 页面不会 404：服务器会把 `index.html` 返回给浏览器，前端路由再渲染对应页面。

## 为什么 `baseURL: ''` 是关键

[web/src/lib/http-client.ts](../web/src/lib/http-client.ts)：

```ts
export const api = axios.create({
  baseURL: '',
  withCredentials: true,
})
```

`baseURL: ''` = 使用浏览器当前地址的源：

| 你打开的地址 | `/api/status` 实际请求到 | 谁处理 |
| --- | --- | --- |
| `http://localhost:5173` | `http://localhost:5173/api/status` | Rsbuild 代理到 3001 |
| `http://localhost:3001` | `http://localhost:3001/api/status` | Go 直接处理 |

如果写成 `baseURL: 'http://localhost:3001'`，开发时会变成跨域请求，Cookie 和鉴权都会出问题。

## 鉴权是怎么过去的

管理后台用 **Cookie + Bearer 双轨**：

1. 登录接口返回 access token，前端存进 Zustand（`stores/auth-store.ts`）
2. 请求拦截器自动加头：

```ts
config.headers.Authorization = `Bearer ${accessToken}`
```

3. `withCredentials: true` 让浏览器同时带上 Session Cookie
4. 后端 [middleware/auth.go](../middleware/auth.go) 同时接受这两种凭证
5. 遇到 401 时，响应拦截器调用 `refreshAuthentication()` 刷新，成功后自动重放请求

`/v1` 的 AI 转发则是另一套：客户端传自己的 `Authorization: Bearer sk-xxx`，由 `middleware.TokenAuth()` 校验 API Key，和管理后台登录态无关。

## 流式响应（SSE）能穿过代理吗

可以。Rsbuild 的代理基于 http-proxy，默认支持 SSE。需要注意的是：

- 代理超时时间要足够长
- 不要在 `/v1` 路径上加 gzip（项目在 `api-router.go` 只给 `/api` 加 gzip，转发路径不加）

## 一个请求的完整时序（开发模式）

```
1. 用户点击"渠道管理"
2. 前端路由 /channels → features/channels/index.tsx
3. 组件 useQuery 调用 getChannels()
4. feature api.ts → api.get('/api/channel/?p=1')
5. axios 拦截器加 Authorization
6. 浏览器请求 http://localhost:5173/api/channel/?p=1
7. Rsbuild 代理到 http://localhost:3001/api/channel/?p=1
8. Go: router/api-router.go → middleware.AdminAuth → controller.GetAllChannels
9. controller → model.GetAllChannels → GORM → 数据库
10. common.ApiSuccess 返回 { success: true, data: ... }
11. 浏览器收到 JSON
12. React Query 缓存数据，组件重新渲染表格
```

## 常见故障排查

| 现象 | 可能原因 | 检查 |
| --- | --- | --- |
| 前端页面 404 | 访问了 3001 但没 build | 改用 5173 |
| 接口 404 | 后端没启动或端口不对 | `netstat -ano | findstr :3001` |
| 接口 502 | 代理目标错了 | 看 `web/.env.development` |
| 一直跳登录页 | 登录态失效或 Cookie 没带 | 浏览器 Network 看 401 |
| 改了前端没反应 | 访问的是 3001 | 改用 5173 |
| 改了后端没反应 | 没启动 Air | 确认终端 1 在跑 `air` |
| 端口被占用 | 旧进程没退 | `netstat -ano | findstr :3001` 后结束进程 |
