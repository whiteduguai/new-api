# 01 整体架构

## 一句话概括

new-api 是一个 **Go 单体 HTTP 服务**：

- 对外提供两类接口：`/api/*` 管理后台接口、`/v1/*` AI 转发接口
- 内嵌一个 React 单页应用作为管理控制台
- 所有数据落在 SQLite / MySQL / PostgreSQL，可选 Redis 缓存

## 目录地图

| 目录 | 职责 | 你什么时候会改它 |
| --- | --- | --- |
| [main.go](../main.go) | 程序入口：加载配置、初始化数据库/缓存、启动 HTTP 服务、注册后台任务 | 很少改 |
| [router/](../router) | 路由表：把 URL 映射到 controller | 新增接口时改 |
| [middleware/](../middleware) | 中间件：鉴权、限流、CORS、日志、请求体处理 | 改权限/限流时改 |
| [controller/](../controller) | HTTP 处理层：解析参数、调 service/model、返回 JSON | 新增接口时改 |
| [service/](../service) | 业务逻辑：计费、渠道选择、任务轮询、日志生成 | 改业务规则时改 |
| [model/](../model) | 数据层：GORM 模型和查询 | 改表结构/查询时改 |
| [relay/](../relay) | AI 转发子系统：请求协议 helper + 各厂商适配器 | 改转发逻辑/加厂商时改 |
| [relay/channel/](../relay/channel) | 每个上游厂商一个包（openai、claude、gemini…） | 加厂商/改请求格式时改 |
| [relaykit/](../relaykit) | 独立 Go 模块：协议 DTO 与格式转换，必须能独立构建 | 改协议转换时改 |
| [tokenkit/](../tokenkit) | 独立 Go 模块：token 计数 | 改 token 估算时改 |
| [setting/](../setting) | 配置项与热更新（运营设置、计费设置、模型倍率…） | 加配置项时改 |
| [common/](../common) | 公共工具：JSON 封装、响应封装、环境变量 | 加通用能力时改 |
| [dto/](../dto)、[types/](../types)、[constant/](../constant) | 请求/响应结构和常量 | 加字段时改 |
| [i18n/](../i18n) | 后端多语言（邮件、错误消息） | 加后端文案时改 |
| [plugins/tasks/](../plugins/tasks) | JS 任务插件 | 加任务平台时改 |
| [web/](../web) | React 前端源码 | 改管理后台时改 |
| [electron/](../electron) | 桌面封装 | 一般不改 |

## 两条主链路

### 链路 A：管理控制台（`/api`）

```
浏览器 React 页面
   │  axios: GET /api/channel/?p=1
   ▼
router/api-router.go        注册 URL → controller
   ▼
middleware                  限流 → UserAuth / AdminAuth
   ▼
controller/*.go             解析参数、校验、组装响应
   ▼
service/*.go 或 model/*.go  业务逻辑 / GORM 查询
   ▼
common.ApiSuccess()         { success, message, data }
```

特点：同步请求响应，返回 JSON，前端用 React Query 管缓存。

### 链路 B：AI 转发（`/v1`）

```
AI 客户端（OpenAI SDK 等）
   │  POST /v1/chat/completions  Authorization: Bearer sk-xxx
   ▼
router/relay-router.go      /v1 路由组
   ▼
middleware.TokenAuth()      校验 API Key → 得到用户和额度
   ▼
middleware.Distribute()     根据模型/分组选择一个上游渠道
   ▼
controller.Relay()          预扣费 → 调 helper → 失败重试 → 结算/退款
   ▼
relay/*_handler.go          按协议分发（chat/claude/gemini/image/audio…）
   ▼
relay/channel/<provider>/   把请求转换成厂商格式并发往上游
   ▼
上游 AI 服务
```

特点：流式响应（SSE）、需要计费、需要重试和渠道切换。

## 分层依赖方向

```
router → middleware → controller → service → model
                         │            │
                         └─→ relay ───┘
                              │
                              └─→ relaykit / tokenkit（独立模块）
```

规则：

- `model` 不应该反向依赖 `controller`
- `relaykit` / `tokenkit` 不能 import 根模块的包
- 业务规则优先放 `service`，`controller` 只做 HTTP 适配

## 进程启动时发生了什么

看 [main.go](../main.go) 的 `main()`：

1. `InitResources()`：加载 `.env` → `common.InitEnv()` → 初始化数据库 → 初始化 Redis → 初始化 i18n
2. 初始化渠道缓存、定价缓存
3. 启动后台 goroutine：配置同步、渠道自动更新、任务轮询、订阅额度重置、系统实例上报
4. 创建 Gin 引擎，挂全局中间件
5. `router.SetRouter()` 注册所有路由
6. 监听 `PORT`（你的配置是 3001）
7. 等待 `SIGINT` / `SIGTERM`，优雅关闭

## 数据与配置的区别

项目里有两类"配置"，新手最容易混淆：

| 类型 | 存在哪里 | 怎么改 | 例子 |
| --- | --- | --- | --- |
| 环境变量 | `.env` 或进程环境 | 改 `.env` 后重启 | `PORT`、`SQL_DSN`、`REDIS_CONN_STRING` |
| 运行时配置 | 数据库 `options` 表 | 管理后台 → 系统设置，立即生效 | 站点名称、模型倍率、计费规则 |

`setting/` 下的包会把数据库配置加载进内存，并周期性同步（`model.SyncOptions`）。

## 新手最容易踩的坑

1. **以为改前端要重启 Go**：开发时不用，5173 有 HMR。
2. **以为改 Go 要重启前端**：不用，Air 会自动重启后端。
3. **访问 3001 看不到热更新**：3001 是生产构建，开发请用 5173。
4. **接口返回 HTTP 200 但 `success: false`**：这是项目约定，业务错误不走 HTTP 错误码。
5. **直接 import `encoding/json`**：项目要求走 `common.Marshal` / `common.Unmarshal`。
6. **加数据库字段只测 SQLite**：项目要求三种数据库都验证。
