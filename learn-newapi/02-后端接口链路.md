# 02 后端接口链路

## 一个请求经过的文件顺序

以"获取礼品码列表"为例：`GET /api/redemption/?p=1&page_size=10`

```
1. main.go                    进程启动时已注册路由
2. router/api-router.go       redemptionRoute.GET("/", controller.GetAllRedemptions)
3. middleware                 全局限流 → AdminAuth 管理员鉴权
4. controller/redemption.go   GetAllRedemptions(c)
5. model/redemption.go        GetAllRedemptions(startIdx, pageSize)
6. common/gin.go              ApiSuccess(c, pageInfo) 输出 JSON
```

对应代码：

- 路由：[router/api-router.go](../router/api-router.go) 第 309-320 行
- 控制器：[controller/redemption.go](../controller/redemption.go) 第 16-27 行
- 模型：[model/redemption.go](../model/redemption.go) 第 28-60 行

## 第 1 站：router —— URL 到函数

[router/api-router.go](../router/api-router.go) 用 Gin 的 Group 组织接口：

```go
redemptionRoute := apiRouter.Group("/redemption")
redemptionRoute.Use(middleware.AdminAuth())   // 整个组都要管理员
{
    redemptionRoute.GET("/", controller.GetAllRedemptions)
    redemptionRoute.GET("/search", controller.SearchRedemptions)
    redemptionRoute.GET("/:id", controller.GetRedemption)
    redemptionRoute.POST("/", controller.AddRedemption)
    redemptionRoute.PUT("/", controller.UpdateRedemption)
    redemptionRoute.DELETE("/:id", controller.DeleteRedemption)
}
```

你需要记住的约定：

- `apiRouter := router.Group("/api")`：管理后台接口前缀
- `redemptionRoute.Use(...)`：给整组挂中间件
- `/:id`：路径参数，controller 里用 `c.Param("id")` 取
- 同一个 `GET /` 和 `GET /:id` 可以共存，Gin 会按精确度匹配

其他路由文件：

| 文件 | 作用 |
| --- | --- |
| [router/api-router.go](../router/api-router.go) | 管理后台 `/api/*` |
| [router/relay-router.go](../router/relay-router.go) | AI 转发 `/v1/*`、`/v1beta/*`、`/pg/*` |
| [router/web-router.go](../router/web-router.go) | 前端静态资源与 SPA 回退 |
| [router/task-router.go](../router/task-router.go) | 异步任务查询 |
| [router/video-router.go](../router/video-router.go) | 视频任务 |
| [router/plugin-router.go](../router/plugin-router.go) | 插件协议 |

## 第 2 站：middleware —— 鉴权与限流

常用中间件在 [middleware/auth.go](../middleware/auth.go)：

| 中间件 | 作用 | 使用场景 |
| --- | --- | --- |
| `UserAuth()` | 校验登录会话，要求任意登录用户 | 用户自己的 Token、日志 |
| `AdminAuth()` | 校验登录会话且角色是管理员 | 渠道、礼品码、系统设置 |
| `TokenAuth()` | 校验 `Authorization: Bearer sk-xxx` 的 API Key | `/v1` AI 转发 |
| `TokenAuthReadOnly()` | 只读 API Key 校验 | 用量查询 |
| `CriticalRateLimit()` | 敏感操作限流 | 改密码、取 Key |
| `GlobalAPIRateLimit()` | 全局 API 限流 | `/api` 全局 |

鉴权通过后，中间件会把用户信息写进 Gin Context，controller 用这些函数读：

```go
userId := c.GetInt("id")                       // 用户 ID
role := c.GetInt("role")                       // 角色
tokenId := c.GetInt("token_id")                // API Key ID
group := c.GetString("group")                  // 用户分组
```

## 第 3 站：controller —— HTTP 适配层

controller 只做四件事：

1. 取参数：`c.Param`、`c.Query`、`c.ShouldBindJSON`
2. 校验参数
3. 调 service 或 model
4. 用 `common.ApiSuccess` / `common.ApiError` 返回

最小例子 [controller/redemption.go](../controller/redemption.go)：

```go
func GetRedemption(c *gin.Context) {
    id, err := strconv.Atoi(c.Param("id"))
    if err != nil {
        common.ApiError(c, err)
        return
    }
    redemption, err := model.GetRedemptionById(id)
    if err != nil {
        common.ApiError(c, err)
        return
    }
    common.ApiSuccess(c, redemption)
}
```

### 响应格式（非常重要）

成功：

```json
{
  "success": true,
  "message": "",
  "data": { }
}
```

失败：

```json
{
  "success": false,
  "message": "错误原因"
}
```

注意：`common.ApiError` 默认 **HTTP 状态码仍是 200**。前端判断成功与否看 `success` 字段，不看 HTTP 状态码。只有鉴权失败、请求体过大等少数情况才用真实 HTTP 状态码。

### 分页约定

列表接口常用 `common.GetPageQuery(c)`：

```go
pageInfo := common.GetPageQuery(c)
items, total, err := model.GetAllRedemptions(pageInfo.GetStartIdx(), pageInfo.GetPageSize())
pageInfo.SetTotal(int(total))
pageInfo.SetItems(items)
common.ApiSuccess(c, pageInfo)
```

前端传 `p`（第几页）和 `page_size`（每页多少）。

## 第 4 站：service 与 model

怎么选：

| 情况 | 放哪里 |
| --- | --- |
| 纯数据库增删改查 | `model` |
| 多表操作、事务 | `model` 或 `service` |
| 涉及计费、渠道选择、任务、缓存 | `service` |
| 只给一个 controller 用的简单逻辑 | 直接写在 controller |

`model` 用 GORM：

```go
type Redemption struct {
    Id          int            `json:"id"`
    Key         string         `json:"key" gorm:"type:char(32);uniqueIndex"`
    Status      int            `json:"status" gorm:"default:1"`
    Quota       int            `json:"quota" gorm:"default:100"`
    DeletedAt   gorm.DeletedAt `gorm:"index"`
}
```

规则：

- 主键交给 GORM，不要写 `AUTO_INCREMENT`
- 行锁用 `lockForUpdate(tx)`，不要用 GORM v1 的 `Set("gorm:query_option", ...)`
- 原生 SQL 必须考虑三种数据库的引号、布尔值差异
- 新字段要能同时在 SQLite / MySQL / PostgreSQL 上迁移

## 第 5 站：返回

`common.ApiSuccess` / `common.ApiError` / `common.ApiErrorT` 都在 [common/gin.go](../common/gin.go)。

- `ApiError(c, err)`：把 Go error 转成 `success:false`
- `ApiErrorT(c, "English message")`：带翻译的错误消息，消息本身是前端 i18n 的 key
- `ApiSuccess(c, data)`：标准成功响应

## AI 转发链路（补充）

`/v1` 比 `/api` 复杂，入口在 [controller/relay.go](../controller/relay.go) 的 `Relay()`：

```go
for ; retryParam.GetRetry() <= common.RetryTimes; retryParam.IncreaseRetry() {
    channel := getChannel(c, relayInfo, retryParam)   // 选渠道
    newAPIError = relayHandler(c, relayInfo)          // 调协议 helper
    if newAPIError == nil {
        return                                        // 成功
    }
    // 失败：记录、判断是否重试
}
```

`relayHandler` 按请求类型分发（[controller/relay.go](../controller/relay.go) 第 35-60 行）：

| 请求类型 | 处理函数 |
| --- | --- |
| `/v1/chat/completions` | `relay.TextHelper` |
| `/v1/responses` | `relay.ResponsesHelper` |
| `/v1/embeddings` | `relay.EmbeddingHelper` |
| `/v1/images/generations` | `relay.ImageHelper` |
| `/v1/audio/*` | `relay.AudioHelper` |
| Claude 原生格式 | `relay.ClaudeHelper` |
| Gemini 原生格式 | `relay.GeminiHelper` |

每个 helper 内部再通过 `GetAdaptor(apiType)` 找到具体厂商：

```go
// relay/relay_adaptor.go
func GetAdaptor(apiType int) channel.Adaptor {
    switch apiType {
    case constant.APITypeOpenAI:
        return &openai.Adaptor{}
    case constant.APITypeAnthropic:
        return &claude.Adaptor{}
    // ...
    }
}
```
