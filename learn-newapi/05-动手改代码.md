# 05 动手改代码

这章给 5 个高频场景的完整步骤。每步都标了要改哪个文件。

## 场景 1：给管理后台加一个页面

目标：新增 `/my-tools` 页面，只有管理员能进。

### 后端（如果要数据）

1. 在 [router/api-router.go](../router/api-router.go) 里加路由组：

```go
myToolsRoute := apiRouter.Group("/my_tools")
myToolsRoute.Use(middleware.AdminAuth())
{
    myToolsRoute.GET("/", controller.GetMyTools)
}
```

2. 新建 `controller/my_tools.go`：

```go
func GetMyTools(c *gin.Context) {
    items, err := model.GetMyTools()
    if err != nil {
        common.ApiError(c, err)
        return
    }
    common.ApiSuccess(c, items)
}
```

3. 在 `model/my_tools.go` 里写 GORM 查询。

### 前端

4. 新建路由文件 `web/src/routes/_authenticated/my-tools/index.tsx`：

```tsx
export const Route = createFileRoute('/_authenticated/my-tools/')({
  component: MyTools,
})
```

5. 新建 feature 目录 `web/src/features/my-tools/`：

```
my-tools/
├── index.tsx       页面
├── api.ts          接口
└── types.ts        类型
```

6. `api.ts`：

```ts
import { api } from '@/lib/api'

export async function getMyTools() {
  const res = await api.get('/api/my_tools/')
  return res.data
}
```

7. 在页面里用 `useQuery` 调用。

8. 文案加到 `web/src/i18n/locales/` 的七个 JSON 文件。

### 验证

```powershell
# 终端 1 已经 air 在跑，保存后自动重启
# 终端 2
cd web
bun check -b
```

浏览器打开 `http://localhost:5173/my-tools`。

## 场景 2：给已有接口加一个字段

以礼品码为例，增加"备注"字段。

1. `model/redemption.go` 的 `Redemption` 结构体加字段：

```go
Remark string `json:"remark" gorm:"type:varchar(255)"`
```

2. 启动时 GORM 的 `AutoMigrate` 会自动加列（三种数据库都要验证）。
3. 前端 `web/src/features/redemption-codes/types.ts` 加类型。
4. 表单和表格里展示该字段。
5. 七个语言文件加对应文案。

注意：项目要求数据库改动必须在 SQLite、MySQL、PostgreSQL 上都实测。

## 场景 3：新增一个 AI 厂商渠道

这是 `relay` 子系统的核心扩展点。

1. 在 `relay/channel/<厂商名>/` 新建包，通常至少包含：

```
relay/channel/myprovider/
├── adaptor.go      实现 channel.Adaptor 接口
├── constants.go    默认地址、模型列表
└── dto.go          请求/响应结构
```

2. 在 [constant/](../constant) 里加渠道类型和 API 类型常量。
3. 在 [relay/relay_adaptor.go](../relay/relay_adaptor.go) 的 `GetAdaptor` 里注册：

```go
case constant.APITypeMyProvider:
    return &myprovider.Adaptor{}
```

4. 如果该厂商支持流式 `stream_options`，把渠道加进 `streamSupportedChannels`。
5. 如果请求需要转发给上游，可选标量字段必须用指针 + `omitempty`：

```go
Temperature *float64 `json:"temperature,omitempty"`
```

这样客户端不传时是 `nil`（会被省略），传了 `0` 时仍是 `0`（会发送）。

6. 在管理后台"渠道"页面选择新渠道类型测试。

> 涉及计费的改动（价格、usage 解析、扣费）必须先读 [.agents/rules/billing.md](../.agents/rules/billing.md)。

## 场景 4：改系统设置里的一个配置项

系统设置的配置存在数据库 `options` 表，通过 `setting/` 包加载。

1. 在 [setting/operation_setting/](../setting/operation_setting) 或对应设置包里加字段。
2. 在 `setting/` 的默认值初始化里赋默认值。
3. 后端读取处用对应 getter。
4. 前端设置页在 `web/src/features/system-settings/` 下加表单项。
5. 保存走 `controller.UpdateOption`（已有接口，一般不用新增）。
6. 七个语言文件加文案。

要点：运行时配置不需要改 `.env`，保存后由 `model.SyncOptions` 同步到内存。

## 场景 5：改一个页面的文案或样式

最快的一类改动。

1. 找到页面：`web/src/features/<模块>/index.tsx` 或 `components/`。
2. 文案用 `t('English key')`。
3. 在 `web/src/i18n/locales/zh.json` 加中文翻译，其余六种语言也要加。
4. 样式优先用 Tailwind 类。
5. 如果涉及布局或交互，按 `web/AGENTS.md` 补回归测试。

命令：

```powershell
cd web
bun check -b
bun run lint
```

## 改动前的通用检查表

| 问题 | 去哪看 |
| --- | --- |
| 这个功能属于哪个模块？ | `web/src/features/` 目录名 + `controller/` 文件名 |
| 接口路径是什么？ | 前端 `api.ts` 里的 `/api/...`，后端 `router/api-router.go` |
| 需要什么权限？ | 路由组上的 `middleware.AdminAuth()` / `UserAuth()` |
| 数据表在哪定义？ | `model/*.go` |
| 是否涉及计费？ | 是 → 先读 `.agents/rules/billing.md` |
| 是否改了数据库？ | 是 → 三种数据库都要验证 |
| 是否加了用户可见文案？ | 是 → 七个语言文件 |

## 提交前必须执行的检查

```powershell
# 根目录：Go
go build ./...
make test

# web 目录：前端
bun check -b
bun run lint
bun run test
bun run build

# 改了 relaykit / tokenkit 还要在各自目录执行
GOWORK=off go build ./...
```

## 新手常见错误

1. **在 `controller` 里写复杂业务逻辑**：应下沉到 `service`。
2. **前端 `api.ts` 写完整 URL**：只写 `/api/...`。
3. **直接改 `routeTree.gen.ts`**：它是自动生成的。
4. **忘了加中间件**：新接口默认没有鉴权，必须显式挂 `AdminAuth` / `UserAuth`。
5. **忘记 i18n**：直接写中文字符串，不符合项目规范。
6. **只测 SQLite**：数据库改动必须三库验证。
7. **改 Go 后没等 Air 重启完成就测**：看 Air 日志出现 `running...` 再操作。
